Short-KV MXFP8 attention: roofline and optimization analysis
2026-11-13 UTC

Outcome
No large fixed-shape kernel gain was validated. The current winning worktree was kept unchanged.
A metadata-carry prototype improves the ten short shapes by 1.065% on GPU 1 and 0.850% on GPU 0.
Its output and LSE are bitwise identical on these tested seed-7 shapes. One GPU-0 case regresses 0.27%.
This prototype remains experimental: other seeds, BF16-Q, other tile sizes and long KV were not validated.
The previous estimate of almost 2x short-KV headroom used the 4-GiB streaming read ceiling.
Size-matched paired references give a much smaller gap under the measured protocol.

Matched reference
Known inputs: same PR batch-432 H4/D128 short shapes, prepared E4M3 Q/K/V and E8M0 scales.
Attention uses the existing balanced persistent schedule, BM128 and 512 CTAs, exact-exp policy.
Read reference loads as many bytes as the earlier calibrated FetchSize estimate for each shape.
It reads uint32 words and stores only a per-block checksum. All checksums are verified.
Both runners use the same 256-MiB cache flush and alternating 50 samples x 3 rounds.
A preceding independent 0.610-ms GPU compute kernel keeps the queue occupied while the host submits
flush/start/kernel/end. It is outside the measured interval and does not access attention inputs.
Adding this guard changes the representative paired timings by less than 0.4%.
This argues against host submission gaps as the main cause of the lower short-call rate.

Why the read reference matters
Cold uint8 streaming read calibration: 256 MiB 2.87 TB/s, 320 MiB 3.11 TB/s, 384 MiB 3.32 TB/s.
Cold uint32 read calibration on the second GPU: 256 MiB 2.89 TB/s, 320 MiB 3.12 TB/s,
384 MiB 3.35 TB/s, 1 GiB 4.34 TB/s and 4 GiB 5.04 TB/s.
Byte unpack/reduction overhead therefore does not explain the size dependence.
A linear fit to the best uint32 times has a 43.95-us intercept and 5.31-TB/s asymptotic slope.
That fit is descriptive. It does not identify a hardware pipeline stage or prove an unavoidable cost.
A further paired sweep uses 4-, 32-, 128- and 256-KiB read blocks and 4/8 warps.
Best control_short_1 read reference is 121.86 us vs attention 143.58 us (84.9%).
Best candidate_short_4 read reference is 108.60 us vs attention 128.00 us (84.8%).
The small-call reference remains substantially below the 4-GiB throughput after this sweep.
Applying the 5.1-TB/s large-stream figure to a roughly 350-MB short call overstates demonstrated headroom.

Baseline resident-wave occupancy: control_short_1 94.71%, candidate_short_4 93.45% of observed peak
in the traced shader engine eight CUs. These are neither full-GPU nor MFMA utilization numbers.
The baseline has substantial sampled stalls at vmcnt waits associated with:
  - ItemTile -> sequence -> prefix offsets and K/V pointers, including next-item prefetch.
  - Q payload and scale loads near the first QK stage.
  - K/V tile completion before the following MFMA stage.
The short workload has few tile iterations, so startup and epilogue costs amortize poorly.
Slow exact-exp softmax is retained; enabling the existing approximate fast-exp globally had earlier
added short-shape accuracy failures. Accuracy was not relaxed to get a performance result.
On the selected control trace, sampled scalar global-load hits fall from 416 to 368 with carry metadata,
while sampled exp hits stay at 14144. This supports the removed metadata reload mechanism.
Captures are on different GPUs; do not compare their cycle totals as a paired performance result.
Per-wave stalls overlap and must not be summed as whole-GPU runtime fractions.

The apparent initial 0.6% packed-Q-scale gain shrinks to 0.1% in the full ten-shape confirmation.
Predecoded descriptors, redundant-final-prefetch removal, a single item per workgroup, exponent-scale
log arithmetic, AGPR enablement, reduction-tree changes, spill sinking, relaxing compiler scheduling
barriers, wider Q loads, and Q-prefetch reordering did not provide a consistent worthwhile gain.
No synchronization waits were removed from the correctness contract.
Graph replay was slower by about 5-8 us in the paired read/attention test on this stack.
ROCm rejected external captured event timing. Internal captured events also could not provide valid
elapsed-time handles. Those failed attempts are logged; the queue-prefix test avoids that limitation.

A practical way to raise throughput when independent work is available
Packing eight independent copies into a single packed-varlen call raises batch432 to3456.
Throughput gain is 1.3177x geometric mean across all ten short shapes,
range 1.2590..1.3515x.
All eight outputs and LSE equal the original output/LSE repeated, bit for bit.
It is a changed workload, not a fixed-shape kernel speedup. Call latency increases to about 0.8-1.0 ms.
Use it only when independent requests can be batched and the latency tradeoff is acceptable.
The 1/2/4/8 scaling experiment fits approximately 45-49 us of intercept plus a per-batch term.
That is evidence for amortization; it does not identify the intercept with one hardware mechanism.
Batching dependent attention layers is not an equivalent transformation.

Next kernel methods
Carry metadata is a small, reviewable candidate. It needs full edge-case and accuracy validation before adoption.
For more substantial gains, investigate producer/consumer overlap that increases outstanding memory work
without increasing LDS/VGPR footprint enough to reduce residency, and faster softmax that meets accuracy gates.
Reducing tile size alone previously lost latency hiding: the K/V LDS footprint stayed large while each CTA had fewer warps.
Any redesigned small-query path must change operand buffering/occupancy along with tile geometry.
Benchmark a size-matched memory reference and report latency/useful work alongside bandwidth, so redundant
reads are not mistaken for progress toward a meaningful roofline.
