Validated short-attention entry-point improvement
2026-11-13 UTC

Outcome: short prepared scheduled calls improve 2.03% on GPU 0 and 1.92% on GPU 1.
Long calls improve about 0.3%. No matrix arithmetic or quantization recipe was changed.
The current shape-matched read-reference fraction is 87.26% geometric mean, versus 85.68% before.
This is an empirical reference ratio, not a proven physical hardware-utilization percentage.
Against the older 4-GiB streaming-read calibration, current short throughput is 53.24%.
Preparation and schedule construction are excluded from all these timings.

Implementation
1. For scheduled workloads averaging fewer than 4096 KV tokens per sequence, carry decoded
   item metadata and K/V pointers into the next persistent iteration instead of reloading them.
   Async copies, waits, buffer alternation, stage boundaries and output ownership remain.
   Long workloads retain the original loop form. Non-scheduled callers retain the original path.
2. ForwardWorkSchedule records needs_empty_fill from known CPU query/KV lengths.
   If no query-bearing sequence has empty KV, omit the separate _fill_empty launch.
   Unknown/no schedule and empty-KV cases retain that launch. Its conservative field default is True.
   No GPU offsets are read back to compute the flag. The existing schedule/offset consistency contract applies.
3. Add a nonempty regression profile to exercise the skipped-fill path with real output rows.

Rejected directions
Two Q-payload prefetch placements preserve bits but provide no consistent useful gain.
Quadratic/cubic exponent corrections reduce approximation error but add instruction/register
cost and slow the short kernel. They are not in the accepted implementation.
No accuracy gate was relaxed and the existing approximate fast-exp policy was not expanded.

Scope and next steps
The improvement applies to the prepared scheduled path. No schedule still uses conservative filling.
Schedule creation and operand preparation must be amortized by the caller.
For more throughput, batching independent short calls remains a separately validated 1.32x option,
with increased call latency. It is not a fixed-shape kernel speedup.
Larger fixed-shape gains now call for deeper operand-buffer/occupancy redesign rather than the
prefetch and polynomial changes tested here. Those larger changes were not implemented or claimed.
